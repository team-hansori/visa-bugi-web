## 목차 설계

### 1. 요약 (표 형식, 약 1페이지)

공식 표 6개 셀(제품명/소개/사업성/가치/기대효과/관련 이미지)을 아래 내용으로 채운다.

- 제품(아이디어)명: 비자부기(visa-bugi)
- 소개: 이주노동자·유학생 대상 24시간 다국어 생활행정·체류자격 AI 게이트웨이, 4줄 요약
- 사업성: 충북 외국인 8만9,823명 중 이주노동자(2만2,259명)+유학생(1만4,303명) ≈ 41%가 실질 타깃, 지역특화형 비자(F-2-R·E-7-4R) 잠재 대상자와 겹침
- 가치: 규칙기반 계산엔진(환각 최소화) + RAG 안내 + 옵트인 이력관리, 기존 지원센터·포털을 대체하지 않고 잇는 게이트웨이 포지셔닝
- 기대효과: 충북 인구감소지역 정착 전략(지역특화형 비자) 실행 지원 + 유학생 미등록 체류 전환 감소
- 관련 이미지: 요건 충족률 대시보드 · 4단계 여정 타임라인 목업

### 2. 기획 배경

노션 기획서 1절의 논증 순서를 그대로 따른다.

1. 숫자로 보는 충북의 특수성 — 외국인 8만9,823명, 음성 18.1%·진천 13.9%(전국 2·5위)
2. 이주노동자가 겪는 구조적 문제 — 임금체불·사업장 변경 제한 등, 음성노동인권센터 사례
3. 유학생이 겪는 문제 + 충북 특수 맥락 — K-유학생 정책, 미등록 체류자 비율 11.6%
4. **결정적 연결고리** — 지역특화형 비자(F-2-R/E-7-4R/F-4-R) 요건표와 6개 인구감소지역 정착 전략의 접점 (분야 ②에 맞춘 배경 서술의 결론)
5. 충북도의 기존 대응과 한계 — 접근성·파편화·개인화 부재

### 3. 기획 세부설명

#### Part 1. 서비스별 핵심 기능 및 기술 설명

- **3-1 전체 서비스 흐름도**: 사용자 유형 확인 → 상황 발생 → AI 상황 파악(LLM 순차 질문) → 일반행정 문의 / 체류자격 점수 확인 / 위험 키워드 감지 3갈래 → 사용자 이력 저장(벡터DB) → 능동 리마인더
- **3-2 핵심 기능 7개** (표: 기능명 / 설명 / 이주노동자 시나리오 / 유학생 시나리오)
  1. 상황별 대화형 안내
  2. 공문서 촬영 → 모국어 요약
  3. 서류 초안 작성 + 맞춤법 검사 + 제출처 연결
  4. 이력 기반 능동 리마인더(옵트인)
  5. 위험 키워드 감지 시 대상별 전문기관 자동 연결(옵트인과 무관하게 항상 작동)
  6. 체류자격 점수·요건 트래커
  7. 단계별 피드백 집계 → 정책진단 데이터 전달
- **3-3 핵심 기술 스택** (표: 기술 / 역할) — LLM(다국어) · OCR · RAG · 벡터DB 기반 이력 관리 · 규칙 기반 자격요건 계산 엔진 · 키워드 기반 위험 감지+라우팅. 규칙 기반 계산 엔진은 **visa-data의 검수된 공통 데이터 구조(13개 테이블, `visa_criterion_groups`의 AND/OR 논리 트리)를 실제 데이터 기반으로 명시**해 기술적 이해도를 근거로 뒷받침한다.
- **3-4 안전장치 설계**: 계산 로직은 공식 고시 요건표를 구조화한 규칙 기반 엔진만 사용(LLM은 자연어→구조화 값 변환만 담당) · 요건표 정기 갱신 · 화면 내 참고용 안내 문구 상시 표시 · HITL(최종 판단은 항상 사람) 원칙
- **3-5 서비스 스코프 정의**: Tier1(체류자격 트래커·행정 서식 — 직접 구축) / Tier2(건강·직장내괴롭힘·보험 등 — 라우팅만) 구분표, 라이프사이클 4단계(추적→준비→제출→판정) 책임 경계표(비자부기 vs 하이코리아/시군담당부서/출입국사무소/법무부)

#### Part 2. 시나리오별 사용자 여정

두 페르소나는 노션 기획서 3.2절의 가상 인물을 그대로 사용한다(가상 시나리오임을 각주로 명시).

- **페르소나 A — 응우옌 반 A** (27세, 베트남 국적, E-9 비자, 음성군 대소읍 제조업체 3교대, 입국 2년 차)
  여정: 체류자격 점수 확인 요청 → AI 순차 질문(체류기간·연봉·한국어등급) → 규칙기반 엔진이 E-7-4R 요건과 대조 → 부족 항목 안내(한국어능력 2급) → 캘린더 옵트인 추적 제안 → 대화 중 "근로계약서 실제조건이 다르다"는 위험 신호 언급 → ⑤위험 감지가 추적 동의 여부와 무관하게 즉시 음성노동인권센터·외국인근로자지원센터로 연결
  4단계 매핑: 추적(트래커 자가진단) → 준비(사회통합프로그램 등록 안내) → 제출·판정은 관여하지 않음(HiKorea·시군담당부서로 딥링크)

- **페르소나 B — 바트 체첵** (22세, 몽골 국적, D-2 비자, 충북 소재 대학 재학)
  여정: "아르바이트 하고 싶어요" 대화 → 학적+TOPIK 등급 확인 → 허용 시간(주중 25/30시간) 안내 + 제한 업종 사전 경고 → 등록금 고지서 OCR 요약 → 시간제취업 허가 신청서 초안 작성 → 대학 국제교류처 제출처 연결 → 졸업 후 F-2-R 전환 요건을 트래커로 미리 확인
  4단계 매핑: 추적(F-2-R 사전 확인) → 준비(신청서 초안+체크리스트) → 제출(대학 담당부서 딥링크) → 판정 미관여

각 여정은 대시보드 컴포넌트(요건 충족률 %·4단계 타임라인·체크리스트)와 캘린더 카테고리(🔵체류자격/🟢학업근로/🟠생활행정/⚪기타) UI 터치포인트에 매핑해서 제시한다.

### 4. 제품(아이디어) 실현 방안

3부에서 완성형 비전으로 서술한 내용을 현실의 구현 상태와 연결하는 절 — 심사항목 "사업화"의 완성도·타당성에 대응.

1. **현재 구현 상태 (정직하게 구분)**
   - 완료: onboarding, my-hub, OCR 이미지 선택·로컬 미리보기 UI(분석·서버 전송 미연동), Supabase 클라이언트/서버 연동 스캐폴딩, visa-data 공통 데이터 구조(13개 테이블) 설계
   - 데모 단계: calendar(`demo-calendar.tsx`), map(`agency-map-demo.tsx`)
   - 설계 완료·구현 예정: 규칙 기반 자격요건 계산 엔진, LLM 다국어 대화, RAG, 벡터DB 이력 관리, 위험 키워드 라우팅
2. **실현 단계의 예상 문제점과 해결 방안** — 요건표 개정 시 데이터 갱신 체계(visa-data 검수 프로세스), 개인정보 리스크(원본 미저장·사본만 옵트인 보관), 정부 시스템 미연동(하이코리아 등 공개 API 부재 → 딥링크 방식으로 대체)
3. **향후 적용처 및 사업화 방안** — 1차 실증지역: 음성·진천(이주노동자) + 청주·충주(유학생 밀집 대학가), 확장 타깃: 결혼이민자·외국국적동포(F-4-R)
